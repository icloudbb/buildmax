# 设计记录

> **翻译说明：** 本文是[英文原文](../../design/README.md)的简体中文派生翻译。若中英文存在语义冲突，以英文原文为准。

> **受众：** 贡献者 · **状态：** 当前

本文说明 BuildMax 为什么会长成现在这个样子。这些文档是**设计理由，而不是用户
文档**——当某项设计发布了可配置的能力时，面向用户的那一半会放在
[手册](../../../manual)或 [reference/](../../reference/) 中，设计记录本身只
保留权衡取舍和尚未解决的问题。

文档使用稳定、语义化的文件名。请从正在处理的问题出发浏览；每篇记录有一个用于
发现的 primary domain，以及一种说明阅读方式的生命周期。Primary domain 是导航
选择，并非排他的所有权边界。跨 domain 关系应在记录自身中说明。

- **方向**——跨越多个路线图阶段的长期决策。
- **活动计划**——由 [ROADMAP.md](../ROADMAP.md) 跟踪的计划或部分实现工作；记录

## 添加记录

1. 选择简短的语义化文件名，例如 `execution-policy.md`。
2. 说明问题、考虑过的方案、选定方法、状态与阶段。
3. 选择贡献者最可能查找它的 primary domain，并只加入上方一个 domain 表格。
4. 将其生命周期标为方向、活动计划或规范。
5. 如果它交付用户可配置的功能，在 `manual/` 或 `reference/` 编写面向用户的内容，
   并从记录中链接过去。

当记录不再描述当前方向时，**删除它**并移除对应表格行。Git 历史会保留它；参见
[contribute/documentation.md](../contribute/documentation.md)。
