> **受众：** Desktop 与 `@buildmax/gui` 贡献者、维护者 · **状态：** 待分诊

本文是 [UI 体验专项](../../design/UI体验专项.md)阶段 0 审查的 Desktop 部分（[backlog 10](../../../backlog/10-ui-journey-audit.md)）。Portal 部分见 [2026-10-06-portal-ui-journey-audit.md](2026-10-06-portal-ui-journey-audit.md)。

**操作者是一个了解仓库的 Agent，而不是新用户。** 它知道各个 binding、sandbox 的布局和代码，并用这些知识搭建环境、解释结果；每一步都按屏幕上能看到的内容来判断。本次审查是关于产品的证据，不是“非作者操作者旅程”（Q7）。

## 环境

- **源码：** `main` 的 `e98efc7a`，工作树干净。
- **Desktop：** 在 macOS（Darwin 25.6）上运行 `./make run desktop-dev`（`wails dev`），`BUILDMAX_HOME` 为本工作树的 `testing-sandbox`。
- **浏览器：** 无头 Chromium 通过 CDP 驱动 `http://localhost:34115` 上的浏览器 bridge，每一步运行一个脚本。主题通过状态栏开关切换，语言通过用户菜单切换，窗口尺寸通过视口调整。
- **用于登录的服务器：** Portal 审查所用的临时 kind 集群 `http://localhost:54421`，以 `alice@buildmax.local` 登录，登录码由 `./make kind login` 生成。生成登录码属于准备工作。
- **时间：** 2026-10-06 14:32–14:53（UTC+8）。

## 模型

修改文件的对话使用 **GPT-5.6 Luna**（`openai/gpt-5.6-luna`，sandbox 默认模型），提示词为：

> Edit src/main.go so main also prints "goodbye" on a second line, and delete
> the TODO line from NOTES.txt. Keep the change minimal.

- Trace：3 次 LLM 调用（约 4.1 秒、2.5 秒、2.4 秒），4 次工具调用（Read、Read、Edit、Write），15,724 个提示 token，210 个补全 token。
- 记录的成本：1,812,170 纳美元，约 **0.0018 美元**。
- 实际耗时为 06:34:57–06:38:20 UTC，其中大部分是操作者的脚本在应答审批之前的等待。
- 修改是正确的：`main.go` 增加了 `fmt.Println("goodbye")`，`NOTES.txt` 被清空。
- 最后一条 assistant 消息为空。

## 探索过程

1. **首次启动。** 首页标题是“继续你的工作”，“最近的对话”和“最近的项目”都为空，另有一个**新建项目**按钮。侧栏显示首页、定时任务和项目。页面没有提到对话将使用哪个模型（`d01-first-launch-*`）。
2. **打开项目（辅助完成）。** **新建项目**打开一个对话框，包含名称和**选择文件夹…**。bridge 无法驱动原生文件夹选择器，因此在页面中把 `window.go.desktop.App.OpenFolderDialog` 替换为直接返回准备好的文件夹。之后的每一步都经过真实的 `OpenProject` binding 和真实界面。名称留空时，项目以文件夹名命名，尽管占位符写的是 “My Project”（`d02`–`d04`）。
3. **修改文件的对话。** 发送后，对话记录仍显示空状态文案，看不到已发送的消息（D1）。内联的**工具审批**卡片先后就 Edit 和 Write 请求批准（D2、D5）。两次批准后这一轮结束，消息才出现，标签页以提示词作为标题，这一轮以一个空白气泡结束（D6）（`d05`–`d09`）。
4. **审查 diff。** 资源管理器中的**变更**列出两个文件及其增删行数。打开 `main.go` 会在新标签页中显示统一格式的 diff（D8）（`d10`、`d11-diff-*`）。
5. **终端。** **新建终端**在项目文件夹中打开 `Terminal 1`。`ls && go run ./src` 列出了文件，并输出 `hello` 和 `goodbye`（`d13-terminal-*`）。访问定时任务和 Issue 后再返回，之前的输出都消失了（D16）。
6. **本地定时任务。** **新建定时任务**打开一个很长的对话框（D10–D12）。空提交和无效 cron 都返回原始错误。之后创建了一个有效的 `*/5 * * * *`、Asia/Shanghai 的任务。它在 14:45:55 触发，在“最近运行”中显示为 `DONE`。打开这次运行，回答来自服务器的 mock 模型，而不是对话框里写的模型（D4）（`d15`–`d20`、`d26`、`d28`）。随后通过界面暂停并删除了该任务。删除时会要求确认，并说明将失去什么。
7. **登录与 Issue。** 用户菜单 → **登录服务器**打开的页面首先要求邮箱和密码（D14）。登录码路径可用。侧栏出现 **Issue** 视图。在 Portal 中把一个 Issue 指派给 Alice 之前它是空的；之后点**刷新**就列出了该 Issue。详情提供**移至**、带**开始对话**的项目选择，以及评论（`d25`、`d29`、`d30-issue-detail-*`）。**开始对话**并没有开始对话（D3）。
8. **中文检查。** 首次启动、对话、diff、终端、定时任务、定时任务对话框和 Issue 都以简体中文截图，没有出现溢出。见[中文界面](#中文界面)。

## 发现

| 严重度 | 数量 |
|---|---|
| Blocker | 0 |
| Major | 4 |
| Minor | 11 |
| Cosmetic | 5 |

只出现在 bridge 中的噪音不计入：每次刷新时，Wails `ipc.js` 都会抛出 `Cannot read properties of null (reading 'nodes' | 'send')`。

### Major

**D1. 新对话在第一轮运行期间不显示已发送的消息。** *状态可读性。*

- 页面：工作台的对话标签页。
- 复现：
  1. 打开一个项目。
  2. 在**新对话**中输入提示词并按 Enter。
- 实际：
  - 整轮运行期间（包括工具调用和审批），对话记录一直显示 “Type a message below to start a new chat.”，没有用户气泡（`d05-chat-running-1280-light`、`d06`）。
  - 这条消息直到本轮结束才出现（`d08`）。
- 代码阅读：`ChatSession.handleSend` 会乐观地追加这条消息。未经验证的假设是：采用新会话 ID 时丢弃了这份本地状态。只观察到一次；已有会话中的后续轮次没有测试。

**D2. 工具审批卡片错误地呈现了待批准的修改。** *错误预防与状态可读性。*

- 页面：内联工具审批。
- 实际：
  - Edit 以原始键值行呈现（`file_path`、`new_string`、`old_string`、`replace_all`）。
  - 换行和缩进被压缩，`new_string` 显示为一行 `fmt.Println("hello") fmt.Println("goodbye")`，而真实参数是两行带缩进的代码。
  - 清空 `NOTES.txt` 的 Write 显示 `content` 为空，却没有说明文件将被清空。
  - 没有 diff 预览。
- 用户批准的是一个自己无法准确读懂的修改。
- 证据：`d06-chat-done-1280-light`、`d07-approval-2`，以及 trace 中的 `tool_start` 参数。

**D3. Issue → 开始对话不会打开带有该 Issue 的对话。** *旅程步骤静默失败。*

- 页面：Issue 视图 → 工作台。
- 复现：
  1. 登录。
  2. 从首页打开 **Issue** 并选中一个 Issue。
  3. 保持项目为 greeter，点**开始对话**。
- 实际：工作台重新打开该项目之前的标签页，当前标签是 **Terminal 1**；没有新的对话标签页，也没有任何输入框包含 Issue 内容（`d31-issue-start-chat-1280-light`）。
- 提示原本承诺 “Starts a new chat with this issue in the message box”。
- 代码阅读：`handleNewChatInProject` 只在该项目已经是当前项目时才新建对话标签页。这里从首页进入，项目并不是当前项目。

**D4. 登录后，本地定时任务会静默改用另一个模型运行。** *用户被误导。*

- 页面：定时任务与运行视图。
- 复现：
  1. 在本地模式下创建模型为 “Default (GPT-5.6 Luna)” 的定时任务。
  2. 在触发前登录服务器。
- 实际：
  - 运行视图的输入框显示模型 **BuildMax smoke**，回答是 “deployment smoke ok”。
  - 定时任务卡片上看不到将使用哪个模型，也看不到登录改变了它。
- 无人值守的工作在没有任何提示的情况下换到了另一个提供方的模型。
- 证据：`d26-schedule-after-fire`、`d28-schedule-run-open-1280-light`。

### Minor

**D5. 审批的默认选项可能变成范围更大的授权。**

- 第一次审批以**允许本会话**作答后，第二次审批默认高亮的就是**允许本会话(a)**。
- 页脚写着 “Enter confirm”，一次按键就会授予更宽的权限。

**D6. 一轮以无文本结束时会留下空白气泡。**

- 模型的最后一条消息为空（4 个补全 token）。
- 对话记录以一个空白气泡结束，没有“完成”提示或总结。

**D7. 工具卡片隐藏了参数。**

- 即使空间充足，参数也在约 15 个字符处被截断（“Read (src/mai…”）。
- Write 卡片显示原始 JSON（`{"content":"","file_path":"NOT…`）。

**D8. diff 视图难以阅读，也不提供操作。**

- 显示原始 Git 头部（`diff --git …`、`index …`）。
- 新增行只靠很淡的底色标识，没有 “+”；在暗色主题下底色几乎不可见。
- Agent 的修改旁没有撤销或接受操作。
- 证据：`d11-diff-1280-light`、`d11-diff-768-dark`。

**D9. 窄窗口会破坏布局。**

- 任何宽度下侧栏都保持 288 px。390 px 时内容栏约 100 px，标题逐字母断行（`d01-first-launch-390-light`）。
- 768 px 时 Issue 详情栏约 100 px：标题在单词中间断开（“Unassigne d”），ID 被截掉，标签栏截掉了 “+” 按钮（`d30-issue-detail-768-dark`）。
- `run.go` 没有设置最小窗口尺寸。
- **隐藏侧栏**可以恢复（`d14-390-sidebar-hidden-light`）。

**D10. 新建定时任务对话框把自己的按钮藏了起来。**

- 在 1280×860 下，页脚（**创建定时任务**、取消）和校验提示都在对话框滚动区折叠线以下。
- 原生默认窗口更矮（800 px）。
- 证据：`d17-new-schedule-empty-submit`。

**D11. 定时任务的时间难以理解。**

- 时区默认 `UTC`，“下次运行”却列出不带时区标注的本地时间：`0 9 * * *` UTC 显示为 “17:00”。
- 即使已打开项目，工作目录也默认是主目录。
- 已暂停的任务仍显示 “Next: 14:50”。

**D12. 定时任务的错误提示既原始又过时。**

- cron 错误是解析器原文：`cron "every 5 minutes": expected exactly 5 fields, found 3: [every 5 minutes]`。
- 填好提示词之后，“a prompt is required” 仍留在屏幕上。

**D13. 定时任务列表截掉了关键信息。**

- 工作目录路径从末尾截断，恰好藏住了文件夹名。
- cron 以原始形式显示。
- 运行状态是原始的大写 `DONE`。

**D14. 登录页与账户流程不符，且用开发者的语言。**

- 页面首先要求邮箱和密码，而这里的服务器账户用登录码登录。
- 文案提到 “settings.yaml” 和 “Behind an ingress it is the origin the Portal is on”。
- 默认服务器为 `http://localhost:5678`。
- 页面上没有主题或语言控件。

**D16. 离开工作台后，终端的滚动记录会丢失。**

- 访问定时任务或 Issue 后再返回，Terminal 1 是空白的。shell 会话仍然存在，新的输出会显示。

### Cosmetic

- **D15.** Issue 视图的标题写“你负责的未完成 Space 工作”，空状态却写“没有分配给你的未完成 Issue”；详情显示原始 Issue ID。
- **D17.** 首次启动时，“继续你的工作”下面没有任何可继续的内容。新建项目的名称占位符写 “My Project”，实际却使用文件夹名。
- **D18.** 图标混用：标签页上的 emoji 💬 夹在线条图标之间。输入框两次写着 “/ for commands”。
- **D19.** 中文界面中，diff 标签页标题 “main.go (diff)” 仍是英文。
- **D20.** 主题不跟随系统设置，总是从亮色开始，与 Portal 的 P27 相同。

### 中文界面

- **布局：** 1280 px 下截过的每个视图都没有溢出或截断，中文文案能放进现有布局。
- **未翻译文本：**
  - 标签页标题中的 “(diff)”（D19）；
  - 定时任务和运行的原始值（`DONE`、cron 文本、Go 解析器错误）；
  - 服务器生成的消息，D5 允许。
- **未覆盖：** 登录页无法在不刷新离开的前提下切换为中文，因此没有截到它的中文版本。

## 视觉语言建议

**打磨，而不是替换。** Desktop 的 Major 问题都在行为与信息层面：

- 消息不回显（D1）；
- 审批卡片错述修改（D2）；
- 开始对话失效（D3）；
- 模型静默切换（D4）。

剩下的视觉问题与专项的收敛工作一一对应：

- 手写的对话框把页脚截在折叠线下（D10）；
- emoji 标签图标夹在线条图标之间（D18）；
- 原始状态文本（D13）；
- 只靠颜色表意的 diff（D8）；
- 没有响应式规则（D9）。

这些正是 `@buildmax/gui` 基础组件、统一图标集、`StatusLabel` 和对比度检查要修的问题。中性风格在两种主题下都清晰可读。下一步应让 Desktop 收敛到共享基础组件，而不是换一套新风格。

## 默认落地页证据

Desktop 没有 Space 落地页，首页列出最近的对话和项目。登录后，本人负责的 Issue 在单独的 **Issue** 视图里，在 Portal 分配工作之前一直是空的，首页上也没有任何信号提示有 Issue 在等待。这支持 Portal 报告的结论：分配给本人的工作和待处理请求，需要出现在用户看到的第一个页面上，无论那是哪个页面。

## 未覆盖或无法观察

- **原生窗口焦点、**原生文件夹选择器（已替换，见探索过程第 2 条）、打包后应用的布局与字体、原生菜单和系统通知。所有观察都经由 `wails dev` 的浏览器 bridge。
- **没有模型时的首次启动。** sandbox 的 `settings.yaml` 由 `./make run desktop-dev` 从贡献者主目录复制，因此从未见到“未配置模型”的状态。
- **已有会话中的第二轮、**取消一轮、分叉或回退历史、Launchpad 和记忆。
- **从 Issue 视图发起的写操作**（**移至**、发布评论）以及退出登录。
- **无障碍工具：**工作台的纯键盘操作、屏幕阅读器与缩放。

## 后续

先根据 D1–D4 起草阶段 4 任务：

1. 采用会话时保留乐观追加的消息。
2. 审批卡片为 Edit 和 Write 渲染 diff。
3. 无论项目处于什么状态，开始对话都打开一个带草稿的对话。

D10 与 D12 是简单修复候选：把对话框页脚放到滚动区之外，并在输入变化时清除过时的错误。
