# 探索式测试记录

> **翻译说明：** 本文是[英文原文](../../../contribute/exploratory-runs/README.md)的简体中文派生翻译。若中英文存在语义冲突，以英文原文为准。
> **受众：** 贡献者与测试 Agent · **状态：** 当前有效

[探索式测试](../exploratory-testing.md)会话报告的暂存区。探索的输出是一种暂存态：报告提交到此，是为了让贡献者阅读和讨论某项发现，而非归档。每个文件是一次会话的报告，按该指南的简短报告结构撰写。

当一次会话产生了值得讨论的结果时提交报告——已确认或疑似缺陷、可用性障碍、可复用的探索任务章程，或其他贡献者会需要的证据。没有产生持久价值的会话留在被 git 忽略的 `.artifacts/` 工作目录即可，无需提交；不要制造覆盖率记录。

## 生命周期

报告是待处理的工作，而非结论。把每一份都分诊为一个持久产物随后删除，使本目录只保留仍在等待该步骤的报告，永不堆积：

- **转化**：把可执行的发现转为一个修复 PR、一个 [backlog](../../../backlog/README.md) 任务或一个 GitHub issue，遵循 [AGENTS.md](../../../../AGENTS.md)——一项一处。把复现步骤与证据带入那个工作项，然后删除报告；工作此后存在于那里，而不在此。
- **丢弃**：一份报告在被阅读后若无可执行内容，即丢弃。

因为每份报告都会被转化或丢弃，报告从不为跟随当前状态而修改，目录也保持小巧。

## 撰写报告

按 [exploratory-testing.md](../exploratory-testing.md) 中的结构撰写，并内联最短复现步骤与关键观察。`.artifacts/` 下的原始记录是临时的；提交的报告必须在它们消失后仍能自洽。提交前隐去凭据、登录码和无关隐私数据。

## 约定

- 文件名：`YYYY-MM-DD-<surface>-<slug>.md`，例如 `2026-09-13-cli-first-use-continuity.md`。`<surface>` 为 `portal`、`desktop`、`cli`、`worker` 等。
- 报告双语：英文权威，并在 `docs/zh-CN/contribute/exploratory-runs/` 相同相对路径下有一份简体中文镜像，依据 [documentation.md](../documentation.md)。报告与其镜像一同提交，并一同被转化或丢弃。
- 提交报告时在下表新增一行；转化或丢弃报告时移除该行。
