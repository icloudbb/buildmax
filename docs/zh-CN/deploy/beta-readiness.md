## 已接受的限制

首次 Beta 面向私有网络中的单个可信 Space。记录运维人员和参与者已接受以下全部限制：

- [ ] 部署不直接暴露给不可信公共网络。
- [ ] 官方 worker 镜像选择并探测严格 OS 沙箱基线，候选版本必须证明 Bash 受约束。受支持的 worker 配置会禁用 stdio MCP，除非其子进程受声明的边界约束。原生 worker Pod 按文档使用 root、`SYS_ADMIN` 及 seccomp/AppArmor 配置；此次 Beta 不要求 gVisor 这类外层 runtime。
- [ ] 一般 worker 出站没有强制执行的 Pod 级目标 allow-list。已实现的 worker 端口 `NetworkPolicy` 限制控制通道入站，并不限制所有出站流量。
- [ ] Worker 可获得存储凭证或投射的存储身份，因为它直接读写运行状态和 Artifact。
- [ ] SSO、多区域运行和丢失运行的自动重新调度不属于此次 Beta。

## 预检

- [ ] 固定全部三个候选镜像摘要，并归档脱敏后的渲染部署配置。
- [ ] 记录配置的 Worker CPU 和内存请求及上限。服务器在启动时验证这些值，因此需故意提供一个无效资源数量，记录候选版本拒绝启动并指出配置键，而不是启动后调度资源无界的 Job。
- [ ] 记录并实际演练轨迹保留与容量策略。BuildMax 现在提供带审计记录的 `trace.retention_days` 清扫；`0` 仍表示永久保留，因此需要明确的卷容量规划、监控与运维清理流程。
- [ ] 确认 MySQL 和 S3 位于 BuildMax 集群外部，并使用候选服务器和 Worker 将实际采用的相同身份，通过 TLS 访问。
- [ ] 在任何升级演练前，协调备份数据库和存储桶，并记录其标识符。
- [ ] 记录候选版本的 `./make check ci`、直连和托管模式 Compose/kind 冒烟测试、Portal 浏览器 E2E 以及发行归档验证 URL。
- [ ] 记录服务器、Worker 和 Portal 镜像扫描结果、SBOM 位置及来源证明验证结果。

## 运维使用流程

使用已记录的 UI 和运维接口。执行此流程的人不应需要了解源代码。

- [ ] 引导 System Administrator，创建或邀请账户，登录、创建 Space，并用第二种角色验证访问边界。
- [ ] 配置已批准的托管模型，不向客户端分发提供商密钥；随后创建工作，并在 Kubernetes Worker Job 中运行。
- [ ] 检查正在运行的 Job。记录其只读根文件系统、已移除的 capabilities（除 `SYS_ADMIN` 外全部移除）、seccomp 和 AppArmor 配置、缺失的 ServiceAccount 令牌、实际 CPU/内存资源、最小化环境变量及每次运行专属凭证。
- [ ] 查看完成后的输出并下载 Artifact。记录 Artifact 校验和，确认与外部存储中的对象一致。
- [ ] 结合 TaskRun 结果和 Artifact、已存储轨迹、托管调用的模型/令牌账本、配额视图及审计历史解释此次运行。轨迹必须报告实际沙箱边界；Artifact 是单独存储的对象，不能宣称嵌入在轨迹中。
- [ ] 重试工作，确认重试产生新的 TaskRun，拥有独立的轨迹、用量记录、审计轨迹和 Artifact，而不是修改第一次运行。

## 故障演练

针对固定的候选版本执行。每个场景保存时间戳、相关日志、状态界面、TaskRun JSON、轨迹、审计行及 Artifact 列表。

- [ ] 在 Agent 执行时取消运行。它在配置的宽限期内达到 `CANCELED`，保留取消前产生的输出和 Artifact。
- [ ] 强制终止 Worker，使其无法报告。存活回收器在配置宽限期后将运行结算为 `FAILED`，失败原因指出失去 Worker 联系，没有隐式重试；显式重试作为新运行成功完成。
- [ ] 中断数据库访问。`/readyz` 和 System Status 显示依赖故障，无需重新构建服务器，数据库访问恢复后服务正常恢复。
- [ ] 拒绝 Worker 写入对象存储。运行以运维人员可理解的原因失败，保留能安全保留的证据，不留下声称缺失对象可下载的 Artifact 记录。
- [ ] 拒绝服务器读取对象存储，然后恢复。就绪状态和 System Status 显示故障，恢复后无需重写运行数据就能再次读取之前完成的 Artifact。

## 恢复与维护

- [ ] 将协调备份的数据库和存储桶恢复到空白恢复环境。登录并将 Space、Task、TaskRun、轨迹、审计、用量和 Artifact 的标识符及校验和与备份前记录比较。说明实测恢复时间和任何已接受的数据损失。
- [ ] 明确起始模式与提交，不假定已有正式前序发行版。通过真实模式变更演练候选版本声明支持的升级路径；支持二进制回滚时，在升级后模式上运行旧 Server/worker 并重复运维流程。Alpha 主动放弃兼容时，记录受影响字段，明确全新安装/配对恢复流程，并实际演练该恢复路径。不支持回滚是候选限制，不能标为回滚测试通过；不支持数据库降级迁移。
- [ ] 按记录的排空/重启流程轮换 JWT 密钥、数据库凭证、存储身份或凭证及模型凭证。记录现有浏览器会话、执行中运行和已创建 Worker Job 的行为；无需宣称支持热轮换。
- [ ] 记录实际演练的 Kubernetes、MySQL、S3、入口和 TLS 精确版本。这是首个 Beta 的已测试集合，不是对广泛兼容矩阵作出未经支持的承诺。
