# 聊天应用（Telegram）

你可以在 Telegram 里和 BuildMax 助手对话。它就是 Portal 聊天里的那个助手：回答问题、
在 Space 中启动工作，并在它启动的工作结束时在聊天里告诉你。这些对话也会出现在 Portal
聊天里。

前提是你的 BuildMax 服务器已经连接了一个 Telegram 机器人。如果 Portal 的
**Account → Chat accounts** 显示没有连接聊天应用，请联系运维人员（见下文
[运维人员](#运维人员)）。

## 链接你的 Telegram 账号

1. 在 Telegram 里打开机器人。它的名字显示在 Portal 的 **Account → Chat accounts**
   下。给它发任意一条消息。
2. 机器人会回复一个链接和一个形如 `ABCD-EFGH` 的码。打开链接，或者在
   **Account → Chat accounts** 中输入这个码并点 **Look up code**。有效期 10 分钟。
3. Portal 会显示这个码属于哪个 Telegram 账号。确认是你自己的，再点 **Link account**。
   机器人会在 Telegram 里确认。

只确认你自己申请的码：一旦链接，来自那个 Telegram 账号的消息就代表你执行。一个
Telegram 账号只能链接一个 BuildMax 账号。

## 使用

像在 Portal 聊天里一样发消息即可。第一条消息会在你的个人 Space 中开启一个对话，之后的
消息接着这个对话。助手启动任务后，任务完成、失败或被取消时，机器人会发一条简短报告，
附带在 Portal 中查看完整结果的链接。

助手知道当前对话属于哪个 Space，你问起时也能列出你的所有 Space。它不能替你切换
Space，切换请发送 `/space`。在 Portal 聊天里，这些对话会标记为 **Telegram**。

| 命令 | 作用 |
|---|---|
| `/new` | 在当前 Space 中开启新对话 |
| `/space` | 列出你的 Space 并显示当前 Space |
| `/space <编号>` | 切换到该 Space，并在那里开启新对话 |
| `/help` | 显示命令和当前 Space |

机器人只读取文本消息，并且只在与你的私聊中工作。它不在群组中回复，因为群里每个人都会
看到关于你 Space 的回复。

## 解除链接

在 **Account → Chat accounts** 中点击账号旁的 **Unlink**。机器人会立即停止代表你执行；
再次给它发消息会开始一次新的链接。

如果你的 BuildMax 账号被停用，或者你离开了某个对话所在的 Space，机器人会立即停止为它
回答。链接本身会保留，直到你移除它。

## 保持登录

只有在你最近登录过 BuildMax 时，机器人才会代表你执行：默认是最近 90 天内，或运维人员
设置的更短窗口。超过之后，它会对每条消息回复一条重新登录的请求，也不再发送任务报告。
登录 Portal 即可恢复，不需要新的码。**Account → Chat accounts** 会显示你链接的账号
可以执行到什么时候。

这样可以防止聊天链接比你的登录存活得更久：无法再登录 BuildMax 的人，例如离开了一个
通过单点登录（SSO）登录的组织之后，也会停止在聊天中获得服务。

## 运维人员

1. 用 [@BotFather](https://t.me/BotFather) 创建一个机器人并复制它的 token。
2. 把 token 交给服务器。建议通过环境变量，使其不落盘：

   ```bash
   export BUILDMAX_TELEGRAM_BOT_TOKEN=123456:ABC...
   ```

   或者写在 `server.yaml` 中：

   ```yaml
   channels:
     telegram:
       bot_token: ""   # 或设置 BUILDMAX_TELEGRAM_BOT_TOKEN
   public_base_url: https://buildmax.example.com
   ```

3. 设置 `public_base_url`，机器人才能发送确认链接。没有它时，用户需要自己在 Portal
   中输入码。
4. 可选：设置 `channels.sign_in_window`，即一个人最近一次登录后，其聊天链接还能继续
   执行多久。默认为 `session_absolute_ttl`（90 天）。只在身份提供方处为人员办理离职
   的部署，应把它设为自己能接受的聊天访问时限，因为链接没有会话可供身份提供方的登录
   限制去终止。
5. 重启服务器。在 **Administration** 的 **Effective configuration** 中，
   `telegram_bot_token` 会显示为已设置。

机器人通过长轮询接收消息，因此服务器只需要能访问 `api.telegram.org` 的出站 HTTPS，
不需要公网地址或 ingress。不要再为同一个机器人设置 webhook，也不要在其他程序中使用它的
token：Telegram 只把每条消息投递给一个接收方，其他接收方会漏掉消息。多副本部署
（`coordination.mode: redis`）时，同一时刻只有一个副本接收，它停止后由另一个副本接管。

聊天轮次与 Portal 聊天使用同一个对话模型，计量方式也相同：一个轮次发出的每一次模型调用
都计入该对话所属 Space 的 token 配额，并出现在该 Space 的用量中；token 配额已用完的
Space 会收到一条拒绝回复，而不是回答。Telegram 会在它自己的服务器上保存消息；如果你的
部署不能接受这一点，就不要连接机器人。
