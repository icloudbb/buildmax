# 远程控制

远程控制让你在办公桌前开一个 agent 会话，然后通过你的 BuildMax 服务器，从另一台设备
——笔记本或手机浏览器——继续使用它。会话始终跑在你的机器上：你的文件、工具、MCP
服务器都留在本地，另一台设备只是它的一个窗口。

## 开启一个可被触达的会话

先登录，然后开启一个带远程控制的交互会话：

```bash
buildmax --remote-control
buildmax --remote-control --remote-control-name "我的项目"
```

会话会连到它登录的托管服务器，并按你的账号注册自身。可被触达后，日志会打印它被分配到的
会话。`--remote-control-name` 设定另一台设备显示的名称；缺省用你机器的主机名。

远程控制需要登录（`buildmax login`）；没有托管服务器它就无处触达。不传该 flag 时它默认
关闭。

## 从另一台设备观测与驾驭

在另一台设备的 Portal 里打开 **Remote Control**。你会看到自己的活会话，每个带一个在线
圆点。打开其中一个，即可：

- **看它的输出**实时流动。
- **发一条追加消息**——它会被送进运行中的 turn，或在会话空闲时开一个新 turn，就和你在
  终端键入一样。
- **批准或拒绝一次工具调用**——当会话请求权限时。终端和设备谁先回答谁生效，另一端的提示
  随即消散。
- **停止运行中的 turn**——用 Stop 按钮。它只中断这一个 turn，会话仍可用。

## 什么留在你的机器上

执行、文件系统、工具从不离开你的电脑。服务器只中继消息和会话的输出；它是桥，不是
runtime。因为服务器是你自己的 BuildMax 部署，这些中继流量留在你掌控的基础设施上。

## 中断

如果你的网络短暂掉线，会话会自行重连并重挂到同一个会话，所以另一台设备正在看的 URL 继续
有效、它的流会恢复。会话不可触达期间显示为离线；重连后重新在线。如果你关掉终端或退出
进程，会话会离线，直到你再次启动它。

## 尚不可用

opt-in 目前在 CLI/TUI 上。Desktop 与 print 模式的 opt-in、移动推送通知、按设备信任都尚未
构建。
