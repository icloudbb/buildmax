# 模型与模式

BuildMax 以两种模式之一运行，一条命令在它们之间切换。

| | 本地模式 | 托管模式 |
|---|---|---|
| 你处于 | 已登出 | 已登入 |
| 模型来自 | 本机上的 `settings.yaml` | 你登入的那个部署 |
| 提供商凭据 | 你的，在 `settings.yaml` 中 | 部署的；从不发给你 |
| 提示词和工具结果去往 | 直接到每个提供商 | 到那个部署 |

```bash
buildmax models       # 你处于哪种模式，以及它提供什么
buildmax login        # 切换到某个部署的模型
buildmax logout       # 切换回 settings.yaml
```

没有别的东西配置这一点。它没有按模型的设置，因为一个会话要么处于这种模式要么处于那种模式，
其中的每个提示词都去往同一个地方。

## 本地模式

默认模式，也是没有服务器时的整个产品：`settings.yaml` 列出模型，
每个都有自己的端点和 API 密钥，Agent 从本机调用它们。用 [`buildmax init`](快速上手.md) 启动一个。

`default_model` 指明一个新会话从哪个条目开始：

```yaml
default_model: GPT-5.6 Luna
models:
  - model: openai/gpt-5.6-luna
    name: GPT-5.6 Luna
    # …
```

不填它，则第一个条目是默认。在一个会话内部，`/model` 仅为那次对话切换——
下一次会话又从默认开始。

## 托管模式

登入之后，模型变成部署的：

```bash
buildmax login
```

```text
Server URL [http://localhost:5678]: https://buildmax.example.com
To sign in, open this page in a browser and confirm the request:

  https://buildmax.example.com/#/sign-in

Check that the page shows this code: WDJB-MJHT
(The request expires in 10 minutes. Press Ctrl-C to cancel.)

Opened your browser at https://buildmax.example.com/#/sign-in/WDJB-MJHT
Waiting for confirmation…
Signed in to https://buildmax.example.com as you@example.com.
Credentials: OS credential store
```

你在 Portal 中确认这次登录，以你的账户在那里的任一登录方式登录即可：公司的单点登录，或密码。
Portal 会显示该请求及其代码。核对它与终端显示的代码一致后，选择 **确认登录**。如果你刚才并没有发起
登录，或这个链接是别人发给你的，请选择 **拒绝**。终端会写出它登录的账户，所以被错误账户确认时一目了然；
运行 `buildmax logout` 即可撤销。

通过 SSH 连接，或在没有显示环境的 Linux 主机上，该命令不会打开浏览器。请在任何能使用 Portal 的设备上
打开打印出的页面，并在那里输入代码。`--no-browser` 在任何地方都起同样作用。请求有效 10 分钟；被拒绝
或已过期的请求会给出一条消息并以非零状态退出，不保存任何内容。

`buildmax login --password` 改为询问你的邮箱与密码，或管理员提供的登录码，与此前的 `buildmax login`
相同。它只在部署允许你的账户用密码登录时可用，而 SSO 部署往往只把密码留给管理员。

在 Desktop 中，打开侧边栏底部的用户菜单，选择 **登录服务器**，然后填写你打开 Portal 时使用的地址。
页面会询问该服务器的账户如何登录，并据此布局：

- 所有人都可用密码时，邮箱与密码表单在前，下面是 **在浏览器中登录**。
- 只有管理员使用密码时，浏览器按钮在前，密码表单收在 **管理员使用密码登录** 之后。
- 关闭了密码登录时，只有浏览器按钮。

配置了单点登录时，按钮会写出它的名称，例如 **在浏览器中通过 Okta 继续**。选择它会在浏览器中打开
Portal，并显示需要核对的代码，以及 **重新打开浏览器**、用于其他设备上浏览器的 **复制链接** 和
**取消**。你一确认，Desktop 就会登录。如果无法连接服务器，页面会如实说明，而不是猜测。

新账户或忘记密码时，在密码表单下选择 **忘记密码，或已有登录码？**，输入管理员提供的登录码。除非设置了
`server_url`，地址一开始为空。该页面自带语言和主题切换。同一台机器上的 CLI 与 Desktop 共用一个登录，
因此登录其中一个就同时登录了两个。

那个部署提供的每个模型都对你可用——一个 Space 是你与谁协作，而不是什么在给模型设卡。
`buildmax models` 列出它们并说明提示词去往哪里：

```text
Signed in to https://buildmax.example.com. Prompts, tool schemas, and tool
results go there.

Models this deployment offers:
  NAME    CONTEXT   DEFAULT
  Fast    128000
  Deep    200000    yes
```

在你登入期间，你的 `settings.yaml` 模型原封未动且不被使用。`buildmax logout` 把它们带回来。

你得到的是：部署持有提供商凭据，所以你的机器上从不存有其中之一，并且它记录每次调用的花费。
它的价格随模型列表一起下发，所以会话页脚、`buildmax info` 和 `buildmax usage` 会显示你登入期间各会话的花费，
Portal 的 **Usage** 页面也会汇总它们。
改变的是你的数据去往哪里：**提示词、工具模式和工具结果都经过那个服务器。**
这正是这种模式的意义所在，也正是为什么每个界面都说明你处于哪一种——
`buildmax models`、`/model` 面板，以及 TUI 页脚。

## 二者从不混合

一个已登入的会话只看到部署的模型。一个已登出的只看到 `settings.yaml`。二者互不替补：

- **一个宕机的部署不会回退到你的本地模型。** 会话拒绝启动，并说明你的登入仍然有效：
  等部署恢复后重试，或用 `buildmax logout` 转到本地工作。
  回退会把你为一个受治理的部署所写的提示词改发给一个用你自己密钥的提供商。
  Desktop 会显示一条带 **Retry** 的横幅，部署恢复应答后自动消失；它不会让你登出。
- **一个过期或被吊销的登入不会自行变成本地模式。** BuildMax 会说会话结束了并等待：
  重新登入，或用 `buildmax logout` 转到本地工作。在你选择之前，即使部署已经拒绝了它，你的登入也保持原样。
- **一个被禁用的账号**有它自己的提示：在管理员重新启用之前，重新登入无济于事，
  所以可选的是去找管理员，或者 `buildmax logout`。
- **一段对话停留在它开始时的模式中。** 它的第一轮会记录提示词发往哪里。
  登入或登出后再续接它会被拒绝，而不是把它的历史重放到别处；请在新模式下开始一个新会话。
- **Desktop 定时任务保持保存时的模型和模式。** 在表单中选择 **默认** 会保存默认值在那一刻所指的模型，
  保存时还会记下它在哪里运行：本机，或你登录的部署。卡片会同时显示两者。另一模式中的同名模型是
  不同的提供商，所以登入或登出后，卡片会说明此定时任务不在这里运行，下次触发会因此失败，
  而不是改到那里运行。编辑并保存定时任务即可在新模式下运行它。定时任务开始记录模型之前保存的
  定时任务会保持暂停，直到你编辑并保存它。**最近运行**和每次运行的聊天都会显示该次运行使用的模型。

因此离线工作就是 `buildmax logout`——一条命令，以及一个关于你的提示词去往哪里的明确决定。

## 检查它

`buildmax doctor` 把模式作为第一项检查来报告，同时报告它背后的模型是否真的能用：

```text
[OK]   mode: signed in to https://buildmax.example.com: its models serve every prompt
[OK]   settings.yaml: not present, and not needed while signed in
```

登入时，`settings.yaml` 是可选的，其中的模型也不会被探测。
登出时，它报告本地模式，然后检查 `settings.yaml` 中的每一个条目——
一个端点、一个密钥、一个没在运行的本地守护进程。

`buildmax me` 也会询问部署，所以一个已被部署吊销的登入会被报告为不可用，而不是已登入。
