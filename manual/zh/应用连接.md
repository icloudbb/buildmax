# 实验性应用连接

本地插件可以在 `connector.yaml` 中声明少量固定的 HTTP 操作。CLI 通过 OAuth
连接用户账户，并仅调用这些已声明的操作。这是实验性的本地功能，尚无工作区或
单次 Agent 运行授权。

如果服务已经提供 MCP，可使用 [MCP 服务器连接](MCP服务器.md)。它通过服务端
提供的工具定义进行发现，不需要在插件中另行声明固定的 HTTP 操作。

## 试用 Gmail 样例

1. 将 [`sample-plugins/gmail-connector`](../../sample-plugins/gmail-connector)
   复制到 `<BUILDMAX_HOME>/plugins/gmail-connector`，默认位置是
   `~/.buildmax/plugins/gmail-connector`。
2. 创建 Google OAuth **桌面**客户端，启用 Gmail API，并把其客户端 ID 设为
   `BUILDMAX_GMAIL_CLIENT_ID`。按 Google 要求配置同意界面和测试用户。
3. 运行 `buildmax plugin validate ~/.buildmax/plugins/gmail-connector` 检查声明，
   然后在本地终端运行 `buildmax connect gmail-connector`。命令会打开浏览器，
   同时输出授权 URL 以备手动打开；它等待最多两分钟接收本机回调，然后保存
   可刷新的令牌。
4. 运行 `buildmax app gmail-connector profile` 或 `buildmax app
   gmail-connector list_messages`，执行两项声明的读取操作。

草稿写入需要 `{"message":{"raw":"<base64url MIME message>"}}` 形式的 JSON。
在交互式终端运行 `buildmax app gmail-connector create_draft --json '<body>'`。
CLI 会显示 JSON，并要求输入 `gmail-connector/create_draft` 后才发送。
非交互式 Agent 调用会被拒绝。JSON 预览只包含编码后的 `raw` 值；请另外
核对解码后的 MIME 邮件内容。

Google 可能要求验证该样例申请的 OAuth scope。自动化测试使用本地假服务商，
未用真实 Google 账户验证。Google 的 `gmail.compose` scope 还允许发送邮件，
尽管连接器只声明创建草稿。CLI 声明的操作范围不会缩小服务商令牌本身的权限。
参见 [Gmail scope 列表](https://developers.google.com/workspace/gmail/api/auth/scopes)
与[草稿 API 指南](https://developers.google.com/workspace/gmail/api/guides/drafts)。

## 连接器声明

已安装插件的根目录放置一个 `connector.yaml`。它声明
`auth.authorization_url`、`auth.token_url`、`auth.client_id_env`、
`auth.scopes`、`api_origin` 和命名的 `operations`。每项操作有固定的
`method`、`path` 和 `effect`。原型允许无请求体的 GET/读取，以及带 JSON
请求体的 POST/写入；端点需使用 HTTPS，本机回环测试服务可使用 HTTP。
操作路径不能包含查询参数、片段、目录回溯或变量。插件不包含令牌或授权。
`buildmax plugin validate` 检查声明，`buildmax plugin status` 列出操作。

连接令牌默认存于操作系统凭证存储，并以 `BUILDMAX_HOME` 和插件名区分。
如果该存储不可用，连接会失败。显式设置 `BUILDMAX_CREDENTIAL_STORE=file`
时，令牌保存为 `<BUILDMAX_HOME>/connections/<plugin>.json`。Unix 上文件
权限为 0600；Windows 由文件系统 ACL 控制访问，不使用 Unix 权限位。可以访问
本机用户账户或未隔离 shell 的程序仍能读取该文件。
同一变量也影响 BuildMax 服务器登录凭证的存储方式。

CLI 将操作限制到固定 API 主机，拒绝跨主机重定向，刷新即将过期的令牌，并
限制请求和响应体大小为 1 MiB。服务商仍可能拒绝 scope、限制请求速率或修改
API。原型尚无断开连接命令、多账户、持久调用记录或 Desktop 审批界面。
要阻止之后的调用，可在服务商撤销访问权。拥有未隔离 Bash 和网络权限的本地
Agent 可以绕过此 CLI；连接器声明不是通用的 Agent 权限边界。
